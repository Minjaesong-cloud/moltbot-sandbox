# 마디아 컨펌 실전 패턴 (자막 기반)

마디아의 컨펌·강의 영상 30편의 자막에서 추출한, 실제 컨펌 중 반복되는 지적 패턴과
구체 수치. UI를 만들거나 리뷰할 때 이 수치를 기본값으로 쓴다.
(자동 생성 자막이라 표기 오차가 있을 수 있으나 수치·지시는 원 발언 그대로다.)

## 타이포그래피 — 컨펌에서 가장 많이 나오는 지적

- **폰트가 작다**가 전체 컨펌에서 압도적 1위 지적이다. 기준:
  - 모바일 본문 12~13px → 무조건 작다. **14 이상으로 키운다.**
  - 리스트·카드 타이틀 최소 16. 섹션 타이틀 20(세미볼드).
  - PC 인트로/헤드라인 40~48. 메인 배너 헤드 카피 40.
  - 캡션·시간 표기 13 정도.
- **볼드 남발 금지.** "볼드 빼고", "미디움 정도로만", "레귤러로" — 본문은 레귤러,
  강조는 미디움/세미볼드까지. 위계는 두께가 아니라 크기·컬러 계층으로.
- **폰트 컬러 흐리면 진하게.** 본문은 #111 수준까지 올린다. "사용자는 안 보이면 몰라요."
- 행간 '오토' 금지, 자간 직접 조절. 같은 성격의 텍스트는 화면 어디서든 같은 사이즈
  (썸네일 크기가 달라도 폰트 18/22/15 제각각이면 안 됨).
- 본문 미리보기가 **한 줄만 나올 거면 과감하게 빼라.** 보여줄 거면 3줄.
- 사이즈 감이 없으면: **잘된 서비스(네이버 등)를 캡처해서 내 시안 옆에 놓고 크기를
  재보고 또 재보라.** "계속 캡처해서 재보고 재보고를 연습하세요."

## 정렬

- **기본은 좌측 정렬.** 가운데 정렬을 남발하면 "시선이 꼬불꼬불한 길"이 생긴다.
  검색창 placeholder 가운데 정렬도 금지.
- 정렬 기준선이 라운드·요소 때문에 어긋나 보이는지 확인.

## 레이아웃 (PC/웹)

- 콘텐츠 영역 ~1400px, 최대 브레이크포인트 1920. **슬라이드 화살표 같은 컨트롤도
  콘텐츠 폭(1400) 안에** 들어와야 저해상도에서 안 잘린다.
- 메인 배너 높이 ~600. 배너 인디케이터는 이미지 **안쪽**에, 두께 2px 정도로 얇지만
  존재감 있게.
- 좌측 패널·사이드 메뉴는 **접을 수 있어야** 한다 (좁은 해상도 대응). 로고를 패널에
  박아서 못 접게 만들지 마라.

## 여백 / 그룹

- 여백을 꽉 채우려 하지 마라. "꽉 채울 필요가 없어요. 비워 두세요."
- 묶음(그룹) 디자인을 할 거면 그룹 사이 여백을 **과감하게** 벌려라. 그룹 사이가
  그룹 안보다 좁아 보이는 순간 실패.
- 실전 간격값: 바둑판 그리드 갭 4~6 / 카드 사이 12는 타이트, 기본 16, 여유 20 /
  꽉 찬 리스트 위아래 패딩 12~16.

## 컬러 / 강조

- **무거운 면을 연속시키지 마라.** "위가 센데 밑에도 또 센 게 과연 봐줄까?
  강약 잡아야 된다." 블랙 섹션 다음은 화이트로 뺀다.
- 콘텐츠에서는 보통 **레이블보다 숫자(지표)가 강조**된다. "여기서 중요한 게 8%면
  당연히 8%를 강조해야죠."
- 배경이 그레이면 그 위 요소는 그냥 화이트 — 굳이 또 그레이 박스를 얹지 않는다.
- 보조 버튼의 블랙·브랜드 채움은 너무 세다 → 라인/텍스트/그레이 처리로 낮춘다.
  버튼 안 아이콘은 채움 대신 라인 처리.
- 보조 링크에 빨간색 금지 — "'비밀번호 잊으셨나요'가 빨간색이면 이미 에러가 뜬 것
  같아요."

## 이미지 / 오버레이

- **같은 항목의 썸네일은 비율 통일.** 정사각형과 직사각형이 섞이면 안 된다.
  비율을 하나 정하라(쇼츠 비율 등). 크롭을 당연시하지 마라 — 어디가 잘릴지 모른다.
- 딤드(어둡게): 텍스트 가독용은 **~20%로 살짝**, 선택 상태 표시용은 **40~50% 강하게**.
  그라디언트 오버레이를 2~3겹 중첩하면 이미지가 시커멓게 죽는다 — 1겹만.
- 블러 카드 위 텍스트가 안 읽히면 오퍼시티를 60→85%까지 과감하게 올리되,
  배경 경계가 무너지면 그 방식 자체를 버려라.
- 텍스트가 이미지를 가리면 안 된다. 이미지 강조형 서비스라면 더더욱.
- **이미지 퀄리티 자체가 디자인을 바꾼다.** "이미지만 교체해도 디자인이 확 달라 보이죠?"

## 컴포넌트별 처방

- **인풋/검색**: 입력 중 상태를 설계하라 — 클리어(X) 버튼, 전송 수단, 화면 키보드
  높이까지 고려. 입력이 시작되면 추천 검색어는 숨긴다. "추천 검색어는 입력하기 전에
  노출되는 것."
- **버튼**: 모바일 주요 CTA 높이 ~56. 강조 버튼은 화면에 한둘만.
- **탭**: 선택 상태를 명확히 (채움+그림자 등). 탭을 누르면 한 칸씩 이동하는 흐름도 검토.
- **아이콘**: 타이틀 대비 작으면 안 된다. 16은 대부분 작다 → 20~24. 프로필 20→24.
  잘려 보이는 디테일은 제거. 의미가 안 읽히면 텍스트 병기("데이터"처럼 명확하게).
  밋밋한 화면엔 3D 아이콘으로 무게감을 줄 수 있다.
- **배지/필(pill)**: 채움으로, 좌우 패딩 10~12 / 상하 4 정도로 타이트하게.
- **그래프**: 값이 0~5%처럼 낮을 때 숫자를 어떻게 보여줄지 정책을 정하라.
  (5% 이하 숨김 or 숫자를 막대 밖으로.)
- **라인/그림자**: 폰트 계층이 잡히면 구분선 대부분은 지워도 된다. 카드에 그림자를
  줬으면 그 안 아이콘에 또 그림자를 주지 마라 — 중복.

## 프로세스 / 마인드

- 기획서를 받으면 디자인 전에 **타 사이트 비교·분석부터.**
- "정리만 해도 노멀함은 나온다." 특별하게 만들려 하지 말고 정리부터 하라.
  기능 페이지는 가볍게 — "이런 페이지는 그냥 가볍게만 하세요."
- 상태 시뮬레이션: 입력 중, 접힘/펼침, 좁은 해상도, 두 줄·세 줄 텍스트, 낮은 수치,
  빈 상태에서 화면이 버티는지 돌려본다.
- 요소를 숨기면 **대책이 있어야 한다.** "복잡하니까 다 날려버린다 — 이건 해결책이
  아니에요."
- 컨셉 의도(예: '시원한 느낌')가 실제 화면에서 느껴지는지 스스로 검증하라.
  "시각적으로 이상해서 고치는 게 아니고, 의도한 디자인과 결이 너무 다르잖아."
- 디자인에 자꾸 힘을 주려 하지 말고 "내용을 어떻게 간결하게 정리할 수 있는지"에
  포커스를 맞춰라.
