# 마디아 컨펌 실전 패턴 (자막 기반)

마디아의 강의·쇼츠 40편 + 장편 컨펌(리뷰) 영상 8편의 자막에서 추출한, 실제 컨펌 중
반복되는 지적 패턴과 구체 수치. UI를 만들거나 리뷰할 때 이 수치를 기본값으로 쓴다.
특정 시안 맥락에서 나온 값이므로 절대 규칙이 아니라 디폴트로 취급한다.

장편 컨펌 8편의 도메인: 커머스 주문서 / 커머스 메인 / 온보딩(관심사 선택) /
라인 컨셉 모바일 / 광고 배너 그래픽 / 컨셉 웹 / PC·모바일 반응형 웹 / 금융(송금) 앱.

## 1. 타이포그래피 — 컨펌 지적 압도적 1위: "폰트가 작아요"

- 10px 무조건 작다 → 12 이상. 11 → 13 미디움. 12도 대부분 작다 → 14~15.
- 기준값: 모바일 본문 14~15 / 리스트 본문 13(컬러 #767676) / 리스트 타이틀 16 /
  섹션 타이틀 20 세미볼드 / GNB 메뉴 15 미디움 / 버튼 텍스트 14 이상.
- 커머스 상품 모듈: 브랜드명 14 미디움 → 상품명 16 → 가격 16 볼드 (가격 20은 오히려 큼).
- 금융: 총액 36 / 계좌 가격 18 / 거래내역 가격 16 볼드 / 키패드 숫자 20 볼드.
- PC 웹: 히어로 타이틀 48~56 (얇아 보이면 굵기 말고 크기를 키워라) / 서브 타이틀 36~40 /
  본문 16~18 / 배너 타이틀 22, 본문 15.
- 볼드 남발 금지 — 본문 레귤러, 강조 미디움/세미볼드. 히어로 대형 타이틀은 라이트도 가능.
- 흐린 텍스트 → 본문 #111 수준까지. "색깔만 진하지 이런 텍스트가 눈에 하나도 안 들어와."
- **이미지 크기가 변해도 폰트는 변하지 않는다.** 썸네일이 커지든 작아지든 같은 성격의
  텍스트는 같은 사이즈 (22/18/15 제각각 금지).
- 본문 미리보기가 한 줄만 나올 거면 빼라. 보여줄 거면 3줄.
- 금액 기호 명시: 할인 "-25,000원", 적립 "+2,700P". 수익엔 +나 상승 아이콘.
- 사이즈 감이 없으면 잘된 서비스를 캡처해 옆에 놓고 재보고 또 재보라.
- "폰트만 잘 정리해도 깔끔한 느낌은 누구나 만들 수 있어." (여백+폰트 = 디자인의 70%)

## 2. 정렬

- 기본 좌측 정렬. 가운데 정렬 남발 → "시선이 꼬불꼬불한 길", 가독성 저하.
- 이미지 정가운데 텍스트 → 하단·좌측으로. 가격류 세로 정렬 시에도 좌측으로 몰기.
- 텍스트를 영역에 넣을 때 우측 여백 확보 (좌 4 / 우 16) — 안 밀어 넣으면 붙어 보인다.

## 3. 레이아웃

- PC: 콘텐츠 영역 ~1400px, 최대 브레이크포인트 1920. 슬라이드 화살표 등 컨트롤도
  콘텐츠 폭 안에. 좌우 화살표 버튼 48px, 그리드 밖 애매한 위치 금지(벽면 또는 마진 기준).
- 메인 배너 높이 ~600, 빌보드 높이 480에 콘텐츠 폭 900, 다음 장이 2.5~3단 살짝 보이게.
- 서브 히어로 높이 450, 하단 여백 80.
- 인디케이터: 이미지 안쪽, 도트 8px, 선택바 사각형+오퍼시티 50%. 인디케이터가 있으면
  모바일 좌우 화살표는 빼도 인지된다 (모바일에선 화살표 지양).
- 섹션(코너) 간 여백은 과감하게 — 70도 빡빡할 수 있다. 이미지·그래픽이 강한
  사이트일수록 코너 간 여백을 크게 벌려 강함을 상쇄.
- 좌측 패널·GNB는 접을 수 있어야 (해상도 대응). GNB 두 줄이면 한 줄로 압축.
- 이미지 위 GNB는 상단 그라디언트 50%로 대비 확보.

## 4. 여백 / 라운드

- 여백을 꽉 채우지 마라. "비워 두세요." / "항상 여백을 집착해서 봐 보세요."
- 실전 간격: 바둑판 갭 4~6 / 카드 사이 16, 여유 20 / 아이콘 나열 40 / 강조 코너 56.
- 칩(태그): 상하 6, 좌우 8~14, 칩 사이 8 — "누르기 좀 편해야 돼요."
- 라운드: 탭·칩 8 / 썸네일·카드 16~20 / 정보성 페이지는 라운드 다 빼도 됨.
  안쪽 요소 라운드는 바깥 라운드보다 살짝 작게(안으로 들여서).
  문서 모양 그래픽에 라운드 세게 주지 마라 — "문서에 라운드가 들어가지는 않잖아요."

## 5. 컬러 / 강조 / 이펙트

- 무거운 면 연속 금지 — "위가 센데 밑에도 또 센 게 봐줄까?" 블랙 다음은 화이트로.
- "밝은 게 있으면 어두운 게 있어야 돼요." / "항상 약한 게 있어야 강한 게 빛난다."
- 라인은 연한 그레이(#F1F1F1)로, 면 분리는 여백으로. 폰트 계층이 잡히면 구분선 대부분 삭제.
- 보조 버튼·안내문구·변경/펼치기 버튼은 사용 빈도가 낮으면 텍스트+화살표 수준으로 다운.
  "'변경' 버튼이 그렇게 주도적으로 사용되는 버튼인데 이렇게 강조할 필요가 있나."
- 가격이 있으면 거의 무조건 가격이 1순위 강조. "가격이 제일 잘 보이는 디자인은
  흰 바탕에 블랙으로 크게 쓰는 것."
- 하단 독바(탭바)는 항상 따라다니므로 색을 빼고, 선택된 아이콘에만 색. 섀도우 대신
  글래스 처리도 방법.
- 딤드/그라디언트: 텍스트 가독용 ~20%, 색 배경 오버레이는 80~90%까지, 하단 텍스트용
  그라디언트는 90~100%→0으로 과감하게. 그라디언트 단계는 3단 말고 2단. 중첩 금지(1겹).
- UI 그림자는 "진짜 약하게": 2/4~12, 연하게 8%~20%. 카드에 그림자를 줬으면 안의
  아이콘엔 또 주지 않는다.
- 그래픽(배너 오브젝트) 입체감: 이너 섀도우는 3~4개 겹쳐 타이트한 값으로 쌓는다.
  드롭 섀도우 -4/8 20%, 그림자 원은 레이어 블러 20. 글래스: 라운드 크게+이너섀도우
  X5 Y5 블러15 화이트.

## 6. 컴포넌트별 처방

**버튼** — 사용 빈도로 강도를 정한다. 높이 도톰하게(26·33은 작다, 모바일 CTA ~56,
바텀시트 주 버튼 72). 내부 여백 24/10~12. "땅콩 같은" 좁은 버튼 금지.
더보기는 콘텐츠 하단에서 아래로 펼침, 전체보기는 상단 우측.

**인풋** — 인풋 위 타이틀 대신 플레이스홀더로 대체 가능. '모두 사용' 같은 부속 버튼은
인풋 안으로. 검색 조건 탭도 인풋 안으로. 입력 중 상태 설계(클리어 X, 전송, 키보드 높이,
입력 시작하면 추천 검색어 숨김).

**카드** — 카드는 쉬운 대신 진부하고 마진을 잡아먹는다. "바닥에 뿌리는 디자인이 훨씬
어렵지만 제일 깔끔하다." 카드 안의 카드 금지. 배경 박스로 감싸도 최종 금액 한 곳만.

**상품 모듈(커머스)** — "상품 모듈 하나가 원시값" — 하나를 완성해 전부 파생.
정보 순서: 브랜드명→상품명→가격→태그→상품평. 찜(하트)은 우측 고정.
할인율·가격·정상가 순서 유지, 넘치면 아랫줄로(순서 변경 금지). 한 줄 6개는 넘침 → 5개 이하.
가격 자릿수 허용 정책을 먼저 정한다.

**배너** — 배너에서 제일 중요한 것은 텍스트, 로고는 최하위. "그래픽보다 텍스트가 제일
잘 보여야 돼요." 텍스트 중요도 서열 정의→배치→배경색→그래픽 순서로 작업.
노란색처럼 가독성이 안 나오는 배경색은 색 자체를 바꿔라. 축소 배리에이션은 스케일로.

**아이콘** — 라인 두께 통일(1.5~2px, 3px 섞임 금지). 타이틀 대비 작지 않게(16은 대부분
작다 → 20~24). 원형 컨테이너 안 12·3·6·9시 여백 확보. 의미 정확성(로그인은 들어가는
방향, 로그아웃은 나가는 방향). 의미 모호하면 텍스트 병기. 서비스 바로가기 원 72에
아이콘 52. 밋밋하면 3D 아이콘으로 무게중심. 못 그리면 다운받아 써라.

**탭** — 반드시 선택 상태가 있어야 한다(기본 '전체'). 언더바형: 하단 2px, 폰트 16.
바텀시트 필터의 카테고리 탭은 가로 상단이 아니라 좌측 세로(항목 확장에 유리).

**썸네일/미디어** — 같은 항목은 비율 통일(4:5, 정사각 등 한 벌로 제작해 공통 적용).
"같은 비율로 크기 차이만 줘도 다이나믹한 느낌 난다." 주문서 같은 목적지 페이지에선
썸네일 축소(이미 여러 뎁스에서 본 이미지). 영상 카드 플레이 버튼은 원 배경으로 크게.
프로필·태그가 이미지를 가리면 밖으로.

**뱃지/딱지** — 위치·형태 고정. "찜 아이콘이 딱지에 따라 위치가 왔다 갔다 할 수 없다."
시간·타이머는 썸네일 밖으로. 화이트+오퍼시티 태그는 밝은 이미지에서 안 보인다.

**그래프** — 수치(%) 노출하되 낮은 값(0~5%) 표시 정책을 정한다. 지수 카드는 가로보다
세로 배열. 라인 아래 그라디언트 40→0. 컬러 과하면 올드해 보인다.

**리스트(금융 등)** — 아바타·아이콘 원 56~64, 썸네일 80. 정보 많은 카드일수록
가로 나열보다 세로+좌측 정렬. 최근 항목은 1~3개만 보이고 나머지는 더보기 루트로.

**키패드** — 격자 스트록 제거, 화이트 바탕 면 처리.

## 7. 반복 지적 패턴 요약 (컨펌 빈도순)

1. 폰트가 작다 (8/8편) → 본문 14 기준으로 전체 한 단계씩 업
2. 카드 남용·카드 안의 카드 → 걷어내고 바닥에 뿌리기+여백·계층
3. 계층이 안 잡힘, 다 고만고만 → 중요도 순서 먼저 정하고 강·중·약 분리
4. 보조 요소 과강조 → 빈도 낮은 버튼은 텍스트 수준으로 다운
5. 블랙·라인·원색이 너무 세다 → 라인은 연한 그레이, 강조는 한 곳만
6. 가운데 정렬 남용 → 좌측 정렬
7. 상태·예외 케이스 누락 → 선택 상태, 최대 개수 표기, 자릿수·글자수 확장, 빈 상태
8. 이미지 위 텍스트 가독성 → 딤드/그라디언트/블러, 안 되면 배경색 자체를 교체
9. 벤치마킹 그대로 베낌 → 개념만 가져와 구성을 바꿔 응용
10. 공통 컴포넌트 불일치 → 같은 요소는 같은 디자인으로 돌려쓰기
11. 썸네일·오브젝트 과잉 → 목적지 페이지에선 축소, 오브젝트 수 줄이기
12. 여백 타이트 → 그래픽이 강할수록 여백을 넓혀 상쇄

## 8. 작업 프로세스 (마디아 컨펌 방법론)

1. **맥락 파악** — 페이지 성격(정보성/목적지/컨셉) 정의, 그 목적 기준으로 중요도 서열 수립.
2. **요소·케이스 점검부터** — 누락 필드, 선택/입력 상태, 데이터 확장 케이스를 먼저 찾는다.
3. **전체 스캔** — 톤앤매너·강약·볼륨을 훑고 과강조 지점 표시. 디테일은 그다음.
4. **구도 먼저, 디테일 나중** — 대충 배치해 무게감·느낌 확인("한 판을 먼저 그리는 게
   중요") 후 폰트·여백 정밀 조정.
5. **원시 모듈 하나 완성 후 복제** — 상품 모듈·리스트 아이템 하나를 기준값으로 삼고 전개.
6. **공통 요소 재사용** — 타이틀·버튼·인디케이터는 만들어 둔 것을 돌려써서 통일.
7. **레퍼런스 즉석 검증** — 실서비스를 열어 비교하되 "같은 개념, 다른 디자인"으로.
8. **실기기 스케일로 검증** — 확대 작업 화면에서는 폰트가 작아 보이지 않는다.
   반드시 플레이(실크기) 모드로 확인.
9. **Before/After 비교로 마무리** — 반응형은 PC·모바일을 나란히 놓고 결이 맞는지 확인.
