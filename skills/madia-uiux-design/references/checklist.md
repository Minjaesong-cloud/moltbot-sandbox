# 마디아식 UI 진단 체크리스트 (컨펌용)

시안·화면·구현된 UI를 리뷰할 때 이 순서대로 진단한다.
각 항목은 마디아 영상의 반복 주제에서 도출한 것이며, 지적할 때는 반드시
**(1) 무엇이 문제인지 → (2) 왜 문제인지(원칙) → (3) 어떻게 고칠지(구체 수치)** 순서로 말한다.

## A. 덜어내기 / 복잡도

- [ ] 목적이 불분명한 장식 요소(그라디언트, 그림자, 테두리, 배경 패턴)가 있는가?
- [ ] 요소를 하나씩 가려봤을 때, 없어도 과업 수행에 지장 없는 요소가 있는가?
- [ ] 한 화면에서 수행해야 할 핵심 과업이 2개 이상 경쟁하고 있는가?
- [ ] 덜어낼 때 명분(시선 분산·복잡함·가독성)이 있는가? 반대로 필요한 정보를 이유 없이 뺐는가?
- [ ] 지금 당장 필요 없는 정보(배너, 안내문)가 화면에 상시 노출되고 있는가?

## B. 강조 / 위계

- [ ] 화면에서 시선이 가장 먼저 가는 지점이 실제 핵심 요소와 일치하는가?
- [ ] "강" 수준 강조가 화면에 2개 이상 있는가? (있다면 하나만 남기고 격하)
- [ ] Primary(채움) 버튼이 화면당 1개를 초과하는가?
- [ ] 강조 수단(크기+굵기+컬러+배경)을 한 요소에 3개 이상 겹쳐 썼는가?

## C. 타이포그래피

- [ ] 타입 스케일이 4단계를 초과하는가? (12/14/16/20/24처럼 정리)
- [ ] 본문이 모바일 기준 14px 미만이거나, 행간이 1.4 미만으로 답답한가?
- [ ] 텍스트 컬러 계층(본문/보조/비활성)이 구분되어 있는가? 전부 #000인가?
- [ ] 숫자·금액·날짜 등 핵심 데이터가 레이블보다 약하게 보이지는 않는가?

## D. 컬러

- [ ] 브랜드 컬러가 화면 면적의 20%를 넘게 깔려 있는가?
- [ ] 그레이 단계가 정리되어 있는가? (비슷한 회색 5종이 제각각 쓰이고 있지 않은가)
- [ ] 채도 높은 컬러가 넓은 배경 면적에 쓰였는가?
- [ ] 시맨틱 컬러(오류=빨강 등)가 장식 용도로 오용되고 있는가?

## E. 그룹핑 / 여백 / 정렬

- [ ] 관련 정보끼리 붙어 있고, 무관한 정보와는 떨어져 있는가?
- [ ] 그룹 간 여백 > 그룹 내 여백 관계가 지켜지는가?
- [ ] 간격 값이 4/8 배수 시스템으로 통일되어 있는가? (13px, 19px 같은 값 금지)
- [ ] 여백으로 해결될 곳에 구분선·박스를 남용했는가?
- [ ] 정렬 기준선이 불필요하게 여러 개인가?

## E-2. 컴포넌트 함정

- [ ] 카드 UI 남용: 불필요한 요소까지 카드 프레임으로 감싸 시선을 끊고 있는가?
- [ ] 딤드가 이미지를 다 가릴 만큼 진한가? (텍스트 가독성 확보 수준까지만)
- [ ] 3D 오브젝트·그래픽이 정보를 가리고 있는가?
- [ ] 그래프에 수치(%)가 노출되는가? 값이 아주 낮을 때의 표시도 처리했는가?
- [ ] 좁은 영역이라고 요소 사이즈부터 줄였는가? (사이즈 유지, 배치·정리로 해결)
- [ ] 트렌드 이펙트(글래스모피즘 등)를 가독성 검증 없이 썼는가?

## F. 아이콘

- [ ] 한 화면의 아이콘 스트로크 굵기·스타일(라인/필)·모서리가 통일되어 있는가?
- [ ] 축소했을 때 뭉개지는 과한 디테일이 있는가?
- [ ] 의미가 관습화되지 않은 아이콘이 레이블 없이 단독으로 쓰였는가?
- [ ] 시각적 크기가 보정되어 있는가? (같은 24px인데 어떤 건 커 보이고 어떤 건 작아 보이는 문제)

## G. 정보 노출

- [ ] 사용자가 원하지 않는 정보(배너, 안내문, 중복 알림)가 계속 노출되는가?
- [ ] 상세 정보가 접기/더보기 없이 전부 펼쳐져 스크롤을 낭비하는가?
- [ ] 첫 화면(스크롤 전)에 핵심 과업이 완결되게 들어오는가?

## H. 운영 / 현실성

- [ ] 이미지·영상 비율이 통일되어 있는가? (제각각이면 운영 시 매번 가공 필요)
- [ ] 디자인 가이드(그리드, 컴포넌트 규격)를 지켰는가? 퍼블리싱·개발이 가능한 디자인인가?
- [ ] 저해상도/고해상도, 긴 텍스트, 빈 상태(0건) 등 실제 데이터 케이스에 대응되는가?
- [ ] (웹) 상단/하단/코너 전체의 리듬감과 톤앤매너가 맞는가?

## I. 사용자 관점

- [ ] "사용자가 편할 것"이라는 판단이 뇌피셜인가, 근거(패턴·테스트)가 있는가?
- [ ] 정지 화면이 아니라 실제 사용 흐름(터치, 스크롤, 오류 상황)을 예측해 설계했는가?
- [ ] 화면의 목적(예: 로그인 화면이면 로그인)이 시각 표현에 밀리고 있지 않은가?
- [ ] 계산식·금액 등은 사용자가 익숙한 관습 패턴(영수증식)을 따르는가?

## 진단 리포트 형식

리뷰 결과는 다음 형식으로 정리한다:

```
## 총평 (한두 문장 — 가장 큰 문제 하나를 짚는다)

## 잘한 점 (1~3개, 구체적으로)

## 고칠 점 (심각도 순)
1. [영역] 문제 → 원칙 → 수정안(구체 수치)
2. ...

## 우선순위 한 가지
지금 딱 하나만 고친다면: ...
```
